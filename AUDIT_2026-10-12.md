## A. Repository baseline

**Stack** (unchanged by this audit): Python 3.11 / FastAPI backend · React 18 + Vite + Tailwind
frontend · pywebview desktop shell · SQLite (`zaytoon.db`, `audit.db`, `core.db`) · Ollama (default
LLM provider) + optional OpenRouter · Whisper STT + edge-tts TTS · bounded-ReAct agent engine over
a single `ToolRegistry` gate. No external agent framework was introduced.

**Measured baselines before any edit:**

| Suite | Result |
|---|---|
| Backend (`pytest tests/`) | **46 failed, 2,885 passed, 7 skipped** (250.8 s) |
| Frontend (`npm run verify`) | Passed after `npm ci` |
| Desktop (`pytest tests/`) | **603 passed, 8 skipped** |

The 46 backend failures were pre-existing and split into two classes:

- **42 — shebang fakes on Windows.** `test_virtualization_vmware.py` (28) and `test_vm_tools.py`
  (14) wrote POSIX shebang scripts as fake executables; those cannot run on Windows.
- **4 — platform-truth mismatches.** Health-status vocabulary missing `unverified`;
  workspace relative-path message asserted for `X:/…` (absolute on Windows); glibc address
  shorthand (`127.1`, hex) asserted against a Linux `getaddrinfo`; Darwin CPU test measured with
  the host's `time.monotonic()`, which returns a 0.0 s delta back-to-back on this machine.

The frontend `npm ci` fix was local environment drift (Tailwind 4.3.3 in `node_modules` vs
lockfile 3.4.19) — no repository change.

## C. Implemented changes

25 files modified + 1 new test file · **+863 / −42** · nothing committed.

1. **Router VM routes** (`backend/agents/router_agent.py`, `tests/test_router_routing.py`) —
   ordered keyword rules (`vmware|vmrun|virtual machine(s)|\bvm(s)?\b|guest|hypervisor|ubuntu|parrot|افتراضي`,
   plus the `شغّل` shadda variant) route to `tools` at 0.92 confidence; placed after
   memory/scheduling so specific intents keep priority. 59 routing tests green.
2. **Citations / sources UI** (`frontend/src/hooks/useWebSocket.js`, `components/ChatMessage.jsx`) —
   `sources` frame attaches to the streaming assistant bubble in wire order, otherwise held in
   `pendingSourcesRef` for the `message` frame; the answer renders a Sources list.
3. **Language persistence** (`useWebSocket.js`, `App.jsx`) — chosen language stored under
   `zaytoon-language` and restored on reload (RTL included).
4. **STOP control** (`InputBar`, `ChatView`, `AIFloatingBar`, `App`) — interrupt where the user
   types; tests in both frontend suites.
5. **SkillsView UX** (`SkillsView.jsx`) — search, two-step inline delete confirmation (arm/confirm,
   no modal), transient notices.
6. **Skill-tool runtime resync** (`backend/core/skills/tool_loader.py`, `backend/api/main.py`) —
   sync resync against a per-registry `_skill_tools` map with `_forget` + `report["removed"]`;
   lifespan subscribes to `SKILL_CHANGED` under an `asyncio.Lock`; only lifecycle events publish.
7. **Portable fake executables** (`backend/tests/conftest.py` — shared `write_fake_executable` /
   `fake_exe` fixture: POSIX shebang script, Windows `<name>_runner.py` + `<name>.cmd`) —
   fixed **42** failures with zero product change.
8. **Frontend test isolation** (`App.runtime.test.jsx`) — `stubBrowserApis()` clears
   `zaytoon-language` per test; a dedicated reload test proves persistence. (Fix 3 had leaked `ar`
   into later tests — my own regression, caught and fixed.)
9. **Sources reducer tests** (`useWebSocket.test.js`) — 4 tests: streaming attach, hold-for-message,
   no backward bleed, malformed frame ignored.
10. **Four platform-truth test fixes** (test-side only) — health vocabulary accepts `unverified`;
    workspace test splits relative (portable message) from absolute-uncreatable (`X:/no/such/drive`
    on Windows); `fetch_url` shorthand forms expect `SecurityError "does not resolve"` where
    Windows raises `gaierror`; Darwin CPU test pins the clock with `SimpleNamespace(monotonic=…)`.
11. **TTS honest degradation** (`backend/voice/tts.py`, `backend/api/websocket.py`) —
    `TextToSpeech.last_stream_error` records *why* a stream produced nothing (exception class only,
    never the raw text; reset on start, set on the not-available path and on exception). The
    transport sends **one bilingual notice per session** when `chunk_index == 0` and a string reason
    is recorded and the turn was not cancelled, re-arms on any success, and drops the socket's entry
    on disconnect. The gate requires `isinstance(reason, str)` so MagicMock-driven flow tests are
    untouched; `audio_end` still closes the envelope so the client never sticks. 10 new tests
    (4 in `tests/test_tts.py`, 6 in new `tests/test_tts_silence_notice.py`). Verified live: every
    failed synthesis during E2E produced exactly the advisory, never an exception string.
12. **E2E runner hardening** (`backend/scripts/e2e_scenarios.py`) — recognizes the exact fixed
    advisory sentences (case-insensitive English, corrected Arabic spelling) so the voice-service
    notice can neither veto a passing scenario nor break the wait before `done`; `Turn.note()`
    now reports terminal-ness explicitly for real errors.
13. **Host config** (`backend/.env`, gitignored — *not* a repo change) — `OLLAMA_FAST_MODEL`
    corrected from `qwen2.5-coder:3b` (not installed on this host; caused honest
    `MODEL NOT INSTALLED … ollama pull` messages and health `degraded`) to the installed
    `qwen2.5-coder:3B-Instruct` → health `ok`, zero missing models, and E2E tool turns exercised
    live. Alternative: `ollama pull qwen2.5-coder:3b` to match the documented default.

## E. Remaining work

1. **TTS upstream 403 — external blocker.** Microsoft's synthesis endpoint rejects this client
   while `list_voices` succeeds with the same token. Options: watch for an edge-tts release that
   re-establishes the handshake (likely, since the token/HTTP path still works); add an offline
   fallback (Windows SAPI5 via `pyttsx3` — has *no* Egyptian-Arabic voice by default); or a paid
   neural provider. Until then the product degrades honestly: text always arrives, and one
   bilingual notice explains the silence.
2. **OpenRouter free-pool verification — NOT TESTED this session** (no API key; web search was
   unavailable in the audit session for cross-checks). Run `scripts/check_free_models.py` and
   `scripts/verify_tool_capability.py` once a key is configured.
3. **Scenario 9 flakiness under search-engine rate limits** — consider a per-scenario retry or a
   longer ceiling for the search leg (one live run exceeded 240 s on upstream 429/TLS/timeout).
4. **Documentation drift** — AGENTS.md should record: the VM router rules, the TTS notice contract
   (`last_stream_error` + `_TTS_SILENT_SESSIONS` + `_SPEECH_UNAVAILABLE_*`), the `fake_exe`
   fixture, and this host's `.env` fast-model name.
5. **Pre-existing pytest lingering-thread issue** (non-daemon aiosqlite worker) — cosmetic, but it
   costs every run a watchdog timeout.
6. **Known residuals outside this audit's scope:** `fetch_url` DNS-rebinding mitigation (documented
   in `netguard.py`), skill tool-file editing limitation, desktop live-window smoke not run.
